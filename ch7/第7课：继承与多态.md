欢迎来到第7课，这也是面向对象编程中最激动人心的一环。

在 Python (如 PyTorch) 中，你只需继承 `nn.Module` 并实现 `forward` 方法，得益于 Python 的“鸭子类型 (Duck Typing)”，框架可以无缝调用任何层的 `forward`。但 Python 这种运行时的动态查找是以牺牲性能为代价的。

在 C++中，为了在像 Orin NX 这样的边缘设备上榨干每一滴算力，编译器默认一切都是“静态绑定”的。为了实现类似 PyTorch `nn.Sequential` 能够将不同的 Layer 放在同一个数组里依次调用的功能，我们就必须引入 **虚函数表 (vtable)**，让 C++ 拥有在运行时决定调用哪个函数的动态能力。理解这一课，你就理解了 TensorRT 等推理引擎底层的算子多态调度机制。

### 第一部分：理论基础 (45 分钟)

#### 1. 继承的语法与内存模型

继承允许我们基于现有的类创建新类，复用代码。

- **语法：** `class Derived : public Base {}`。`public` 继承表达了“是一个 (is-a)”的关系，比如“Linear 是一种 Layer”。
- **内存模型：** 当你实例化一个子类对象时，内存中会先排布父类的成员变量，紧接着排布子类特有的成员变量。你可以把子类指针安全地转型为父类指针，因为它的内存开头确实是一个完整的父类对象。

#### 2. 虚函数 (`virtual`)、重写 (`override`) 与动态多态

- **静态多态 vs 动态多态：** 默认情况下，C++ 看你用什么类型的指针调用函数，就执行什么类的函数（编译期决定）。而 **动态多态** 的目标是：使用父类的指针指向子类的对象，调用函数时，真正执行的是子类的函数（运行期决定）。
- `**virtual` 关键字：** 在父类的函数声明前加上 `virtual`，就开启了该函数的动态多态能力。编译器会为这个类生成一张“虚函数表 (vtable)”，在运行时查表来找到真正的函数实现。这会带来极其微小的性能开销，但为了架构的灵活性，这在深度学习框架设计中是绝对值得的。
- `**override` 关键字：** C++11 引入。放在子类重写的函数末尾。它没有实际运行功能，但**强烈建议永远加上**。它的作用是让编译器帮你检查拼写错误和参数不匹配（如果你在子类里把 `forward()` 写成了 `foward()`，没有 `override` 编译器会认为你写了个新函数，有了 `override` 编译器会直接报错）。

#### 3. 纯虚函数与抽象类

- **纯虚函数：** 语法为 `virtual void forward() = 0;`。这表示父类只提供接口，不提供任何实现，强制要求继承它的子类必须实现这个方法。
- **抽象类：** 只要一个类包含至少一个纯虚函数，它就是抽象类（完美等价于 Python 的 `abc.ABC` 加上 `@abstractmethod`）。**抽象类绝对无法被实例化**，你不能 `new Layer()`。

#### 4. 虚析构函数的生死攸关

这是 C++面试的必考题，也是无数 C++ 程序员栽过跟头的地方。
如果你打算通过父类指针来管理子类对象，并最终通过 `delete 父类指针` 来释放内存，**父类的析构函数必须是 `virtual` 的**。
如果不加 `virtual`，`delete` 时只会调用父类的析构函数，子类特有的资源（比如 Linear 层里申请的权重矩阵内存）将永远留在堆里，造成严重的内存泄漏。

### 第二部分：实操实验 (75 分钟)

我们将模拟构建一个极简的神经网络推理引擎。设计一个抽象基类 `Layer`，并派生出全连接层和激活函数层，最后用一个统一的流水线来执行它们。

#### 1. 编写代码 (`nn_engine.cpp`)

我们将所有的类定义在一个文件中以便于快速编译测试。在实际的 C++ 工程中，这些应该被拆分到各自的 `.h` 和 `.cpp` 文件中。

```cpp
#include <iostream>
#include <vector>
#include <string>

// ==========================================
// 1. 定义抽象基类 Layer
// ==========================================
class Layer {
protected:
    std::string name_;

public:
    Layer(const std::string& name) : name_(name) {}

    // 【极其关键】：虚析构函数！确保 delete 基类指针时，能正确调用派生类的析构函数
    virtual ~Layer() {
        std::cout << "[Layer Destructor] Destroying layer: " << name_ << std::endl;
    }

    // 纯虚函数，= 0 意味着 Layer 变成了抽象类 (不能被实例化)
    virtual void forward() = 0;

    // 普通成员函数
    std::string getName() const { return name_; }
};

// ==========================================
// 2. 派生类：LinearLayer (全连接层)
// ==========================================
class LinearLayer : public Layer {
private:
    int in_features_;
    int out_features_;
    float* weights_; // 模拟需要动态分配的权重内存

public:
    LinearLayer(const std::string& name, int in, int out) 
        : Layer(name), in_features_(in), out_features_(out) {
        
        // 构造函数中申请资源
        weights_ = new float[in_features_ * out_features_];
        std::cout << "  [LinearLayer Constructor] Allocated weights for " << name_ << std::endl;
    }

    // 重写析构函数，释放自己的资源
    ~LinearLayer() override {
        delete[] weights_;
        std::cout << "  [LinearLayer Destructor] Freed weights for " << name_ << std::endl;
    }

    // 重写 forward 函数，加上 override 关键字
    void forward() override {
        std::cout << ">>> Executing Linear Layer [" << name_ 
                  << "]: Matrix multiplication (" << in_features_ 
                  << " -> " << out_features_ << ")" << std::endl;
    }
};

// ==========================================
// 3. 派生类：ReLULayer (激活层)
// ==========================================
class ReLULayer : public Layer {
public:
    // 调用基类构造函数初始化 name_
    ReLULayer(const std::string& name) : Layer(name) {}

    ~ReLULayer() override {
        std::cout << "  [ReLULayer Destructor] Destroyed " << name_ << std::endl;
    }

    void forward() override {
        std::cout << ">>> Executing ReLU Layer [" << name_ 
                  << "]: max(0, x)" << std::endl;
    }
};

// ==========================================
// 4. 主程序：推理流水线调度
// ==========================================
int main() {
    std::cout << "--- Building Model Pipeline ---" << std::endl;

    // 核心：使用基类指针 (Layer*) 的容器，统一管理不同的派生类对象
    std::vector<Layer*> pipeline;

    // 在堆上动态实例化派生类，并存入流水线
    pipeline.push_back(new LinearLayer("fc1", 128, 64));
    pipeline.push_back(new ReLULayer("relu1"));
    pipeline.push_back(new LinearLayer("fc2", 64, 10));

    std::cout << "\n--- Starting Forward Pass ---" << std::endl;
    
    // 动态多态的魅力：无需知道具体的类型，只要调用 forward() 
    // vtable 会自动把调用路由到正确的子类实现
    for (size_t i = 0; i < pipeline.size(); ++i) {
        pipeline[i]->forward();
    }

    std::cout << "\n--- Cleaning Up Resources ---" << std::endl;
    
    // 因为使用了 new，必须手动 delete。
    // 这里也是测试虚析构函数是否工作的关键。
    for (size_t i = 0; i < pipeline.size(); ++i) {
        delete pipeline[i]; 
    }
    pipeline.clear();

    std::cout << "--- Program End ---" << std::endl;
    return 0;
}

```

**重点观察现象：**

1. **Forward Pass 阶段：** 循环遍历时，虽然指针类型全都是 `Layer`*，但打印出来的逻辑精确地路由到了 `Linear Layer` 和 `ReLU Layer` 自己的实现中。这就是动态多态。
2. **清理资源阶段：** 当执行 `delete pipeline[i]` 时，你会在日志中清楚地看到，程序**先**调用了 `LinearLayer` 的析构函数释放了权重内存，**然后**自动调用了基类 `Layer` 的析构函数。这证明了虚析构函数完美地防止了内存泄漏。

**课后思考：**
在这个实验的最后，我们不得不用一个 `for` 循环来手动 `delete` 数组里的所有裸指针。如果程序在 `forward` 过程中抛出了异常，或者有人忘了写这段清理代码，辛苦写出的严谨架构瞬间就会崩溃。如何让这些多态指针也能像 Python 对象一样，生命周期结束时“自动”销毁？这就是第8课**智能指针**将要为你解决的终极问题。
