## 第一部分：理论与架构设计 (30 分钟)

### 1. 架构梳理：从“碎片”到“系统”

我们回顾一下前面所学的技术在大型系统中的定位：

* **面向对象 (OOP) 与多态：** 提供“契约”。定义一个 `Operator` 抽象基类，所有的具体算子（Conv, ReLU, Attention）都继承它并重写 `forward()`。这样调度器就可以无视具体类型，统一调度。
* **智能指针 (Smart Pointers)：** 提供“安全”。通过 `std::unique_ptr<Operator>` 转移算子的所有权，让框架在卸载模型时，自动且绝对安全地清理每一层占用的显存/内存，彻底消灭内存泄漏。
* **STL 容器 (`std::map`)：** 提供“映射”。建立字符串名称到对象创建函数的极速查找表。
* **多线程 (Multi-threading)：**（本章实操未包含，但作为延伸）在算子内部的 `forward()` 中，利用多线程将矩阵乘法分块并行执行。

### 2. 设计模式：工厂模式 (Factory Pattern) 与注册表

在 Python 中，通过字符串实例化类非常简单（例如使用 `eval()` 或 `globals()`）。但在强类型的编译型语言 C++ 中，类名在编译成机器码后就“消失”了，变成了内存地址。

**解决方案：**
我们使用一个单例（Singleton）或核心管理类 `OpFactory`。
它内部维护一个字典：`std::map<std::string, 创建该算子的函数>`。
当程序启动时，各个算子主动将自己的名字和“创建函数”挂载到这个字典里。当解析模型结构文件时，工厂只需拿着名字去字典里找，找到函数并调用，就能返回一个智能指针。

## 第二部分：实操实验 (90 分钟)

我们将把这套注册表机制编译为一个供外部调用的动态链接库 (`.so`)，模拟真实的第三方引擎 SDK 交付形式。

### 1. 编写核心代码 (`inference_engine.cpp`)

我们将类的声明和实现集中在一起以便于展示。这段代码充分利用了 C++11 的函数式编程特性（`std::function`）和现代内存管理机制。

```cpp
#include <iostream>
#include <string>
#include <map>
#include <memory>
#include <functional>

// ==========================================
// 1. 抽象基类：所有算子的接口契约
// ==========================================
class Operator {
public:
    virtual ~Operator() = default; // 必须是虚析构函数，保证多态释放安全
    virtual void forward() = 0;    // 纯虚函数，定义前向传播接口
};

// ==========================================
// 2. 具体算子实现
// ==========================================
class Conv2D : public Operator {
public:
    void forward() override {
        std::cout << "[Engine] Executing Conv2D... computing spatial convolution." << std::endl;
    }
};

class ReLU : public Operator {
public:
    void forward() override {
        std::cout << "[Engine] Executing ReLU... applying max(0, x)." << std::endl;
    }
};

// ==========================================
// 3. 核心：算子注册表与工厂类
// ==========================================
class OpFactory {
private:
    // 定义一个类型别名：CreatorFunc 是一个函数，没有参数，返回一个 Operator 的独占智能指针
    using CreatorFunc = std::function<std::unique_ptr<Operator>()>;
    
    // 注册表：将字符串映射到具体的创建函数
    std::map<std::string, CreatorFunc> registry_;

public:
    // 注册函数：向字典中添加算子
    void registerOp(const std::string& name, CreatorFunc func) {
        registry_[name] = func;
        std::cout << "[Factory] Operator registered: " << name << std::endl;
    }

    // 创建函数：根据字符串名字，动态生成智能指针
    std::unique_ptr<Operator> createOp(const std::string& name) {
        auto it = registry_.find(name);
        if (it != registry_.end()) {
            // it->second 就是那个创建函数，调用它 () 即可生成对象
            return it->second(); 
        }
        std::cerr << "[Factory] Error: Operator '" << name << "' not found!" << std::endl;
        return nullptr;
    }
};

// ==========================================
// 4. 对外提供的 C 风格 API，用于封装编译成 .so 库
// ==========================================
// extern "C" 告诉编译器不要对函数名进行 C++ Name Mangling（名字粉碎），
// 确保 Python 的 ctypes 或其他 C 语言程序可以直接加载这个库。
extern "C" {
    void run_mock_inference() {
        std::cout << "\n--- Engine Initialization ---" << std::endl;
        OpFactory factory;

        // 模拟框架启动时的算子注册阶段
        // 使用 Lambda 表达式封装对象的创建逻辑
        factory.registerOp("Conv2D", []() { return std::make_unique<Conv2D>(); });
        factory.registerOp("ReLU", []() { return std::make_unique<ReLU>(); });

        std::cout << "\n--- Parsing Model Graph (Simulated) ---" << std::endl;
        // 假设我们从模型文件 (如 JSON 或 ONNX) 中解析出了以下算子顺序
        std::string model_nodes[] = {"Conv2D", "ReLU", "UnknownOp", "Conv2D"};

        std::cout << "\n--- Execution Phase ---" << std::endl;
        for (const auto& node_name : model_nodes) {
            // 根据字符串动态创建对象
            std::unique_ptr<Operator> op = factory.createOp(node_name);
            if (op) {
                // 如果创建成功，利用多态执行计算
                op->forward();
            }
        }
        std::cout << "\n--- Engine Shutdown (RAII cleans up automatically) ---" << std::endl;
    }
}

```

### 2. 编写 CMake 脚本编译动态库

在工业界，你的推理引擎通常作为库文件发布，而不是直接编译为可执行程序。

在同级目录下创建 `CMakeLists.txt`：

```cmake
cmake_minimum_required(VERSION 3.12)
project(InferenceEngine)

# 要求使用 C++14 或更高标准（为了使用 std::make_unique）
set(CMAKE_CXX_STANDARD 14)
set(CMAKE_CXX_STANDARD_REQUIRED True)

# add_library 指令替代了 add_executable
# SHARED 关键字指示 CMake 生成一个动态链接库 (.so / .dll)
add_library(engine SHARED inference_engine.cpp)

# 设置输出的高级编译优化标志 (模拟 Release 发布)
target_compile_options(engine PRIVATE -O3 -Wall -fPIC)

```

### 3. 编译与测试

在终端中执行外部构建：

```bash
mkdir build && cd build
cmake ..
make

```

执行完毕后，`build` 目录下会生成一个 `libengine.so` 文件。

为了验证它，我们可以写一个只有一行的极简 Python 测试脚本 `test_engine.py` 来加载你编写的底层 C++ 引擎：

```python
import ctypes

# 加载生成的动态链接库 (请确保路径正确)
engine_lib = ctypes.CDLL("./libengine.so")

# 直接调用 extern "C" 暴露的函数
engine_lib.run_mock_inference()

```

运行 `python test_engine.py`，你将看到完整的注册、实例化、多态路由和资源清理日志。
