### 第一部分：理论基础 (60 分钟)

#### 1. 深拷贝 (Deep Copy) vs 浅拷贝 (Shallow Copy)

在 Python 中，执行 `tensor_b = tensor_a` 时，默认发生的是**引用赋值**（浅拷贝），两个变量贴在同一个底层对象上。如果需要完全独立的副本，必须显式调用 `copy.deepcopy()`。

在 C++ 中，如果你没有手动编写拷贝逻辑，编译器会自动为你生成一个。但这个自动生成的函数只会执行**浅拷贝（按成员逐个复制）**。

* **浅拷贝的灾难：** 如果 `Tensor` 类中包含一个指向堆内存的指针 `float* data_`，浅拷贝只会复制这个**地址数值**。
* 结果：`tensor_a` 和 `tensor_b` 共享同一块堆内存。
* 危机爆发：当这两个对象离开作用域时，它们的析构函数都会被触发。`tensor_b` 先销毁，释放了这块内存；紧接着 `tensor_a` 销毁，**再次尝试释放已经被释放的内存**。这会导致操作系统立刻介入并中止程序，抛出经典的 **Double Free (Segmentation Fault)** 错误。


* **深拷贝的解法：** 我们必须接管拷贝过程，重新 `new` 一块同样大小的内存，并将原内存中的数值逐个复制过去。

#### 2. C++ 经典法则：Rule of Three（三法则）

这是 C++98 时代确立的最核心的面向对象准则（在 C++11 引入移动语义后扩展为 Rule of Five）。

**定义：** 如果你的类需要手动定义以下三个函数中的**任何一个**，那么它几乎必然需要同时定义**这三个**：

1. **析构函数 (Destructor):** 负责释放资源。
2. **拷贝构造函数 (Copy Constructor):** 负责形如 `Tensor b(a);` 或 `Tensor b = a;` 的对象创建。
3. **拷贝赋值运算符 (Copy Assignment Operator):** 负责形如 `b = a;` （`b` 已经存在）的赋值操作。

*逻辑闭环：* 需要析构函数意味着你在管理堆内存等资源；既然管理了资源，默认的浅拷贝就一定会引发 Double Free，所以必须手写深拷贝的构造和赋值。

#### 3. `const` 成员函数与 `const` 引用

在严谨的 C++ 工程（特别是底层推理引擎开发）中，`const` 具有极高的契约地位。

* **`const` 引用 (`const Tensor& other`)：**
用于函数传参。它既避免了按值传递引发的昂贵拷贝（对于动辄几十 MB 的多模态大模型特征图至关重要），又通过 `const` 承诺：**“我只读取你的数据，绝对不会篡改。”**
* **`const` 成员函数 (`void print() const`)：**
放在函数声明的末尾。它向编译器承诺：**“调用这个方法，不会改变对象内部的任何成员变量。”**
* *重要推论：* 如果你有一个 `const Tensor&` 对象，你**只能**调用它的 `const` 成员函数。如果你的 `getSize()` 没有标记为 `const`，编译器将拒绝编译。

### 第二部分：实操实验 (60 分钟)

我们将重构上一课的 `Tensor` 类，严格贯彻 Rule of Three。想象我们正在处理自研 VLM 模型输出的特征向量，确保在传递和赋值过程中内存的绝对安全。

#### 1. 完善 Tensor 类的声明与实现 (`tensor_v2.cpp`)

```cpp
#include <iostream>
#include <stdexcept>
#include <cstring> // 用于 memcpy，提供极速的内存块拷贝

class Tensor {
private:
    float* data_;
    size_t size_;

public:
    // 1. 普通构造函数
    Tensor(size_t s) : size_(s), data_(new float[s]) {
        std::cout << "[Constructor] Allocated " << size_ << " floats." << std::endl;
        for (size_t i = 0; i < size_; ++i) data_[i] = 0.0f;
    }

    // 2. 析构函数 (Rule of 3 - Part 1)
    ~Tensor() {
        delete[] data_;
        std::cout << "[Destructor] Freed memory." << std::endl;
    }

    // ----------------- 本节课核心内容 -----------------

    // 3. 拷贝构造函数 (Rule of 3 - Part 2)
    // 触发场景: Tensor b = a; 或 Tensor b(a);
    Tensor(const Tensor& other) : size_(other.size_), data_(new float[other.size_]) {
        std::cout << "[Copy Constructor] Deep copying " << size_ << " floats." << std::endl;
        // 使用 memcpy 替代 for 循环，在底层具有更高的执行效率
        std::memcpy(data_, other.data_, size_ * sizeof(float));
    }

    // 4. 拷贝赋值运算符 (Rule of 3 - Part 3)
    // 触发场景: b = a; (此时 b 已经完成了构造并且拥有自己的内存)
    Tensor& operator=(const Tensor& other) {
        std::cout << "[Copy Assignment] Re-allocating and deeply copying." << std::endl;
        
        // 步骤 A: 自我赋值检查 (极度重要!)
        // 如果外部执行了 a = a;，跳过此检查会导致先把 a 的内存释放了，接下来就无数据可拷
        if (this == &other) {
            return *this;
        }

        // 步骤 B: 释放当前对象已经持有的旧资源
        delete[] data_;

        // 步骤 C: 重新根据源对象分配新内存
        size_ = other.size_;
        data_ = new float[size_];

        // 步骤 D: 深拷贝数据
        std::memcpy(data_, other.data_, size_ * sizeof(float));

        // 步骤 E: 返回自身的引用，以支持连续赋值操作 (如 a = b = c;)
        return *this;
    }

    // --------------------------------------------------

    // const 成员函数：承诺不修改内部状态
    size_t getSize() const { 
        return size_; 
    }

    // 修改内部状态，不能加 const
    void setValue(size_t index, float val) {
        if (index >= size_) throw std::out_of_range("Index out of bounds!");
        data_[index] = val;
    }

    // 打印只读数据，必须加 const
    void print() const {
        std::cout << "Tensor data: [ ";
        for (size_t i = 0; i < size_; ++i) {
            std::cout << data_[i] << " ";
        }
        std::cout << "]" << std::endl;
    }
};

```

#### 2. 编写主程序测试生命周期

在主程序中，我们将主动触发拷贝构造和拷贝赋值，并观察终端的日志输出。

```cpp
int main() {
    std::cout << "--- 1. Testing Normal Construction ---" << std::endl;
    Tensor t1(3);
    t1.setValue(0, 1.1f);
    t1.setValue(1, 2.2f);
    t1.setValue(2, 3.3f);
    t1.print();

    std::cout << "\n--- 2. Testing Copy Constructor ---" << std::endl;
    // 此时 t2 刚刚被创建，触发 Copy Constructor
    Tensor t2 = t1; 
    
    // 修改 t2 的数据，验证深拷贝是否成功（t1 不应受影响）
    t2.setValue(0, 9.9f);
    std::cout << "t1 (Source): "; t1.print();
    std::cout << "t2 (Copied and Modified): "; t2.print();

    std::cout << "\n--- 3. Testing Copy Assignment ---" << std::endl;
    Tensor t3(5); // t3 最初有 5 个元素的空间
    
    // 此时 t3 已经存在，将触发 Copy Assignment Operator
    // 它会先释放自己的 5 个元素的空间，再申请 3 个元素的空间并拷贝 t1
    t3 = t1; 
    std::cout << "t3 (After Assignment): "; t3.print();

    std::cout << "\n--- 4. End of Scope (Destructors will trigger) ---" << std::endl;
    return 0;
}

```

**重点观察现象：**
当程序执行到结尾 `End of Scope` 时，你会看到控制台输出了 **3 次** `[Destructor] Freed memory.`。
分别对应 `t3`, `t2`, `t1` 的销毁（栈对象的销毁顺序与构造顺序相反）。因为我们完美执行了 Rule of Three 实现了深拷贝，它们各自管理着完全独立的堆内存地址，整个析构过程平稳安全，没有任何 Double Free 崩溃。
