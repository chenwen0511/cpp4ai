这是从Python跨越到C++最核心、也是最具挑战性的一课：**内存管理与直接内存访问**。

在Python中，内存是由解释器（通过引用计数和垃圾回收）自动管理的，开发者无需关心变量存在哪里。而在C++中，为了追求极致的运行效率，你需要亲自掌握数据的物理存储位置。这对于未来编写高性能的CUDA算子或部署端侧大模型至关重要。

### 第一部分：理论基础 (60 分钟)

#### 1. 内存地址的概念：栈 (Stack) vs 堆 (Heap)

程序运行时，内存被划分为不同的区域。

- **栈 (Stack):**
- **机制：** 由编译器自动分配和释放。作用域（大括号 `{}`）结束时，变量立即销毁。
- **特点：** 分配速度极快（只需移动栈顶指针），内存连续，不会产生碎片。
- **限制：** 容量极小（Linux系统默认通常为 8MB）。
- **应用：** 存放普通的局部变量、函数参数。如果你尝试在栈上声明一个 100MB 的多维数组，程序会立刻崩溃（经典的 Stack Overflow）。
- **堆 (Heap):**
- **机制：** 由开发者手动申请和释放（下一课会讲 `new`/`delete`）。
- **特点：** 容量极大，受限于机器的物理内存。
- **应用：** 存放大型对象（如图像帧、庞大的模型权重文件、百兆级别的特征向量）。

#### 2. 指针 (`*`) 与取地址 (`&`)

内存可以看作是一个巨大的数组，每一个字节都有一个唯一的编号，这就是**内存地址**。

- **取地址符 (`&`):** 获取一个变量在内存中的具体位置。
- **指针变量 (`*`):** 一种特殊的变量，它里面存的不是普通的数值，而是**另一个变量的内存地址**。
- **解引用 (`*`):** 通过地址，顺藤摸瓜去读取或修改那个地址上的实际数据。

```cpp
int a = 10;
int* ptr = &a; // ptr 存放了 a 的地址

// *ptr 就是解引用，直接修改了 a 的内存
*ptr = 20;     // 此时 a 的值变成了 20

```

- **指针的算术运算：**
这是C++处理连续内存（如展平的张量数据）的高效方式。如果 `ptr` 指向一个 `int` (4字节)，`ptr + 1` 并不是在地址数值上加1，而是向后移动 4 个字节，直接指向下一个 `int` 的位置。

#### 3. 引用 (`&`) 的本质与 Python 对象的区别

引用是C++特有的概念，它是变量的**别名**。

```cpp
int a = 10;
int& ref = a; // ref 是 a 的引用（别名）
ref = 20;     // a 也会变成 20

```

- **与指针的区别：** 指针是一个独立的变量，可以随时改变指向（今天指A，明天指B）；而引用一旦在初始化时绑定了某个变量，就**终生绑定，无法更改**，且必须初始化。
- **与 Python 对象的区别：** Python 的变量本质上都是“对象的引用标签”，你可以让 `x = 10`，然后再让 `x = "hello"`，标签可以撕下来贴到别处。C++的引用是物理内存地址的死绑定，安全且无额外开销。

#### 4. 函数传参：传值 vs 传引用

这是算法工程中最容易引发性能瓶颈的地方。

- **按值传递 (Pass by value):**
默认情况下，C++向函数传递参数时会**完整复制一份数据**。如果传入的是一个包含几百万个浮点数的结构体，每次调用函数都会发生海量的内存拷贝，耗时极长。
- **按引用传递 (Pass by reference):**
函数参数使用引用接收数据。此时传递的仅仅是数据的“别名”（底层传递的是地址的指针），没有任何拷贝开销，时间复杂度为 O(1)。
- *最佳实践：* 如果只需要读取数据而不需要修改，通常使用**常量引用** `const Type&`，既保证了零拷贝的极速性能，又防止了数据被意外篡改。

### 第二部分：实操实验 (60 分钟)

#### 实验 1：通过指针和引用交换变量值

理解数据是如何跨越函数作用域被修改的。

**1. 编写代码 (`swap_demo.cpp`)**

```cpp
#include <iostream>

// 1. 传值（错误示范）：这只是交换了函数内部拷贝的副本
void swap_val(int x, int y) {
    int temp = x;
    x = y;
    y = temp;
}

// 2. 传指针：通过内存地址直接操作原数据
void swap_ptr(int* x, int* y) {
    int temp = *x; // 读取 x 指向的值
    *x = *y;       // 将 y 指向的值赋给 x 指向的内存
    *y = temp;
}

// 3. 传引用：最优雅、最现代的C++写法
void swap_ref(int& x, int& y) {
    int temp = x;  // 就像操作原变量一样
    x = y;
    y = temp;
}

int main() {
    int a = 1, b = 2;
    swap_val(a, b);
    std::cout << "After Pass by Value: a=" << a << ", b=" << b << std::endl; // 失败，依然是 1, 2

    swap_ptr(&a, &b); // 需要显式传入地址
    std::cout << "After Pass by Pointer: a=" << a << ", b=" << b << std::endl; // 成功，变成了 2, 1

    swap_ref(a, b);   // 语法看起来和传值一样，但底层传递了引用
    std::cout << "After Pass by Reference: a=" << a << ", b=" << b << std::endl; // 再次成功，变回 1, 2

    return 0;
}

```

**2. 编译并运行**

在 `ch3/code` 目录下执行：

```bash
g++ swap_demo.cpp -o app
./app
```

**3. 运行结果**

程序输出与如下一致：

```text
After Pass by Value: a=1, b=2
After Pass by Pointer: a=2, b=1
After Pass by Reference: a=1, b=2
```

简要对照：

- **传值**：只在函数内交换了形参副本，调用处的 `a`、`b` 仍是 `1`、`2`。  
- **传指针**：通过地址写入调用方内存，`a`、`b` 变为 `2`、`1`。  
- **传引用**：同样改的是调用方变量，再次交换后恢复为 `1`、`2`。

#### 实验 2：大型数据的性能对比（传值 vs 传引用）

我们使用 C++ 标准库中的 `std::vector`（可动态扩容的数组，类似于 Python 的 List）来模拟一个体积庞大的特征向量。我们将直观地感受到两种传参方式在耗时上的鸿沟。

**1. 编写性能测试代码 (`performance_test.cpp`)**

```cpp
#include <iostream>
#include <vector>
#include <chrono> // 用于高精度计时

// 定义一个别名，代表百万级别的浮点数组
using LargeTensor = std::vector<float>;

// 1. 按值传递：每次调用都会触发底层数据的完整深拷贝
float process_by_value(LargeTensor tensor) {
    float sum = 0;
    // 假设进行一些简单的求和计算
    for(size_t i = 0; i < tensor.size(); ++i) {
        sum += tensor[i];
    }
    return sum;
}

// 2. 按常量引用传递：不发生拷贝，直接读取原内存，且保证不被修改
float process_by_reference(const LargeTensor& tensor) {
    float sum = 0;
    for(size_t i = 0; i < tensor.size(); ++i) {
        sum += tensor[i];
    }
    return sum;
}

int main() {
    std::cout << "Allocating memory for 100,000,000 floats..." << std::endl;
    // 初始化一个包含 1亿个浮点数的大型数组（约 400MB 内存）
    LargeTensor big_tensor(100000000, 1.0f); 

    // --- 测试传值耗时 ---
    auto start_val = std::chrono::high_resolution_clock::now();
    float result_val = process_by_value(big_tensor);
    auto end_val = std::chrono::high_resolution_clock::now();
    std::chrono::duration<double, std::milli> diff_val = end_val - start_val;
    std::cout << "[Pass by Value] Time taken: " << diff_val.count() << " ms" << std::endl;

    // --- 测试传引用耗时 ---
    auto start_ref = std::chrono::high_resolution_clock::now();
    float result_ref = process_by_reference(big_tensor);
    auto end_ref = std::chrono::high_resolution_clock::now();
    std::chrono::duration<double, std::milli> diff_ref = end_ref - start_ref;
    std::cout << "[Pass by Reference] Time taken: " << diff_ref.count() << " ms" << std::endl;

    return 0;
}

```

**2. 编译并运行**

```bash
# 开启 -O3 极致优化标志进行编译，以模拟真实的生产环境
g++ -O3 performance_test.cpp -o perf_test
./perf_test
```

**预期现象：**
在执行时，你会发现 `[Pass by Value]` 会消耗显著的时间（可能需要几十到几百毫秒，这在要求实时性如 30FPS 以上的处理流水线中是致命的），因为它在内存中硬生生复制了 400MB 的数据。而 `[Pass by Reference]` 几乎是瞬间完成的。
