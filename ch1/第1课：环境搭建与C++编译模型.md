欢迎开启C++的学习之旅。对于习惯了 `python script.py` 一键运行的开发者来说，C++最大的不同在于**代码在运行前必须经过严格的编译和链接阶段**。理解这个底层逻辑，是未来在边缘设备或服务器上成功部署AI模型的关键。

以下是第1课的详细教案，包含了理论讲解与实操代码。

---

### 第一部分：理论基础 (45 分钟)

#### 1. C++ 代码的生命周期：从源码到机器码

Python是解释型语言，由解释器逐行翻译执行；而C++是编译型语言，需要通过编译器（如GCC或Clang）将人类可读的源码转换为特定硬件架构（如x86服务器或ARM架构的边缘设备）能直接执行的机器码。

这个转换过程分为四个严格的阶段：

1. **预处理 (Preprocessing):**
* 处理所有以 `#` 开头的指令。
* 例如，`#include <iostream>` 会把 `iostream` 头文件的全部内容直接复制粘贴到你的代码中。`#define` 宏定义也会在这里被展开。
* *输出：纯C++源码文件（通常后缀为 `.i`）*


2. **编译 (Compilation):**
* 编译器进行语法和语义检查。如果你的代码有语法错误（比如少写了分号、类型不匹配），就会在这个阶段报错。
* 通过检查后，编译器将C++代码翻译成底层的汇编语言。
* *输出：汇编代码文件（后缀为 `.s`）*


3. **汇编 (Assembly):**
* 汇编器将汇编语言转换成机器能够读懂的二进制机器指令（目标文件）。
* *输出：目标代码文件 (Object File，后缀为 `.o` 或 `.obj`)*


4. **链接 (Linking):**
* 这是最容易出Bug的阶段。当你调用了外部库（比如OpenCV或TensorRT的函数）时，目标文件中只有该函数的“占位符”。
* 链接器的作用是将你的多个 `.o` 文件，以及所需的静态库 (`.a`/`.lib`) 和动态库 (`.so`/`.dll`) 缝合在一起，生成最终的程序。如果找不到对应的函数实现，就会报经典的 **Linker Error (undefined reference)**。
* *输出：可执行文件或动态链接库*



#### 2. 构建工具链：编译器与 CMake

* **GCC (`g++`) / Clang (`clang++`):** 核心编译器，负责执行上述四个步骤。
* **CMake:** 在实际的工业级项目中（如构建复杂的推理引擎），可能包含成百上千个源文件和复杂的第三方依赖。手动敲 `g++` 命令是不现实的。CMake 是一个跨平台的构建系统生成器，你编写人类可读的 `CMakeLists.txt`，CMake 会自动为你生成底层的 `Makefile`（在Linux下），然后由 `make` 工具调用编译器完成自动化构建。

### 第二部分：实操实验 (75 分钟)

#### 实验 1：环境搭建

我们以 Linux 环境（或 Windows 下的 WSL2）为例，这是AI开发的标配环境。
打开终端，安装必要的编译工具链：

```bash
sudo apt update
sudo apt install build-essential cmake gdb

```

*验证安装：输入 `g++ --version` 和 `cmake --version`，如果输出版本号即代表成功。*

#### 实验 2：Hello World 与单文件编译

创建一个工作目录并编写你的第一个C++程序。

**1. 编写代码 (`main.cpp`)**

```cpp
#include <iostream> // 引入标准输入输出流库

int main() {
    std::cout << "Hello, Embodied AI World!" << std::endl;
    return 0; // 返回0表示程序正常退出
}

```

**2. 使用命令行编译并运行**

```bash
# -o 选项用于指定输出的可执行文件名称，否则默认输出 a.out
g++ main.cpp -o my_app

# 运行程序
./my_app

```

#### 实验 3：多文件编译与体会“链接错误”

在实际项目中，我们通常会将代码拆分成多个文件。假设我们正在编写一个简单的机器人控制器。

**1. 编写头文件 (`robot_controller.h`)** —— *只做声明*

```cpp
#pragma once // 防止头文件被重复包含

// 声明一个初始化机器人的函数
void initRobot(int device_id);

```

**2. 编写源文件 (`robot_controller.cpp`)** —— *具体实现*

```cpp
#include "robot_controller.h"
#include <iostream>

// 实现该函数
void initRobot(int device_id) {
    std::cout << "Initializing Robot on Device ID: " << device_id << std::endl;
    // 模拟硬件初始化逻辑...
}

```

**3. 修改主函数 (`main.cpp`)** —— *调用外部函数*

```cpp
#include <iostream>
#include "robot_controller.h" // 包含声明

int main() {
    std::cout << "System starting..." << std::endl;
    initRobot(0); // 调用其他文件中的函数
    return 0;
}

```

**4. 尝试编译与错误排查**
尝试只编译 `main.cpp`：

```bash
g++ main.cpp -o my_app

```

**现象：** 你会看到一个类似于 `undefined reference to 'initRobot(int)'` 的错误。
**原理：** 这就是一个**链接错误**。编译阶段 `main.cpp` 因为引入了头文件，知道 `initRobot` 的存在，通过了语法检查。但在链接阶段，链接器找不到 `initRobot` 真正的机器码（因为它在 `robot_controller.cpp` 里，而你没有告诉编译器去编译它）。

**正确的多文件编译命令：**

```bash
g++ main.cpp robot_controller.cpp -o my_app
./my_app

```

#### 实验 4：使用 CMake 实现自动化构建

为了告别冗长的命令行，我们将刚才的多文件项目改用 CMake 来构建。

**1. 在当前目录下创建 `CMakeLists.txt` 文件**

```cmake
# 1. 指定CMake的最低版本要求
cmake_minimum_required(VERSION 3.10)

# 2. 定义项目名称
project(RobotApp)

# 3. 指定C++标准为 C++17
set(CMAKE_CXX_STANDARD 17)
set(CMAKE_CXX_STANDARD_REQUIRED True)

# 4. 添加可执行文件目标
# 语法：add_executable(可执行文件名 源文件1 源文件2 ...)
add_executable(my_app main.cpp robot_controller.cpp)

```

**2. 执行标准 CMake 构建流程 (Out-of-source Build)**
在工业界，我们通常会把编译产生的临时文件和源代码分离开来，这被称为“外部构建”。

```bash
# 创建一个专门用于存放编译产物的目录
mkdir build
cd build

# 让 CMake 读取上一级目录 (..) 中的 CMakeLists.txt 并生成 Makefile
cmake ..

# 使用 make 开始真正的编译链接过程
make

# 运行生成的可执行文件
./my_app

```
